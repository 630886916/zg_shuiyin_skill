# zg_shuiyin_skill · 固定水印 + 高清不降级 + 多素材智能拼接

## 零、两条最高铁律

### 铁律 1：默认不询问

**用户说「加水印 / 水印版 / zg_shuiyin_skill」= 整套默认参数照搬，禁止逐项确认、禁止每次问参数。**

- 默认水印图就是 `assets/watermark.png`。**只有用户当次明确说「这次用某某图片当水印」才换**，且只影响当次。
- 默认参数（透明度、大小、位置逻辑、画质、输出）同理：不新说就用默认。
- 用户明确点名某一项时，只覆盖那一项，其余仍走默认。
- 拼接编排也**不打断流程**：理解完直接出片，把剪辑方案随成片一起给，不在出片前反问。
- 禁止因为「怕弄错」而反问；不确定就按默认跑，跑完把成片、方案、质检报告给用户看。

### 铁律 2：路由（决定画质，不可随意改）

| 输入 | 链路 |
|---|---|
| **1 个视频** | **直接加水印，绝不进拼接流程** —— 多一次拼接就多一代重编码，直接违背高清目标 |
| **≥2 个素材**（视频／图片任意混） | 理解 → 编排 → 拼接成完整视频 → **再**给这个完整视频加水印 |
| 1 张图片（边界） | 按多素材最小情况处理：生成 2~5s 片段 → 加水印 |

`wm_pipeline.py` 自动判路由，不需要用户说明。

### 首次使用先自检（装完第一次跑之前）

`npx skills add` / 手工复制都**只搬文件、不装 Python 依赖**。首次调用前先跑一次：

```bash
python scripts/wm_env_check.py
```

- 全 `[OK]` → 直接干活。
- 报缺 `imageio_ffmpeg` / `PIL` / `numpy` / `cv2` → 先 `python -m pip install imageio-ffmpeg pillow numpy opencv-python`，再自检一次。
- **ffmpeg 不用单独装**：`wm_core.find_ffmpeg()` 会自动用 imageio-ffmpeg 自带的那个
  （PATH 里那版 filter 语法有差异，不要用）。
- 缺 `faster-whisper` **不影响出片**，只影响多素材时的「口播转写」辅助线索，可忽略。
- 自检全绿仍提示「找不到技能」→ 确认技能目录在 `~/.workbuddy/skills/zg_shuiyin_skill/`
  （或对应 agent 的 skills 目录），且里面有 `SKILL.md`。

## 一、水印冻结规格（参数唯一来源 = `scripts/wm_config.py`）

| 项 | 默认值 | 说明 |
|---|---|---|
| 水印图 | `assets/watermark.png` | **当前内置「中工LOGO-红色.png」**（1882×719 / RGBA 透明底 / 403KB），随包分发；换图 = 覆盖这个文件，或当次 `--watermark` |
| 透明度 | **50%** | 在图片自身 alpha 上再乘 0.5（`colorchannelmixer=aa=0.5`） |
| 尺寸 | **水印图最长边 = 画面基准边 ÷ 4** | 横屏基准 = 画面宽，竖屏基准 = 画面高；1280 → 320px，1080 → 270px，1920 → 480px；等比缩放、偶数化 |
| 时段 | 全程常驻 | 第 0 帧到末帧 |
| 运动 | **动态浮动** | 缓慢连续斜向漂移，非固定位置 |
| 轨迹随机性 | **确定性伪随机** | 种子 = SHA256(素材相对路径)；同素材每次跑完全一致，不同素材轨迹不同 |
| 轨迹算法 | 双频正弦叠加 | x/y 各用两组不同频率/相位/振幅，形成 Lissajous 式斜动，无跳变、无停顿 |
| 浮动范围 | 全画面可飘，只保证不越界 | 四边留 `max(短边×2%, 8px)` 边距；不额外避让字幕/人脸 |
| 画质 | 视觉无损 | libx264 **CRF14** / preset slow / aq-mode 3；**不缩放、不裁剪、不改帧率、不改时长**（真实素材实测见第六节第 13 条） |
| 音频 | 直通 copy | 非 mp4 兼容音轨才回退 aac 192k，并在报告标注 |
| 输出 | 原片只读 | `<源目录>/水印版/<原名>_水印版.mp4`；处理完逐条立即输出 + 汇总质检报告 |
| 批量 | 整目录递归 | 自动跳过已处理成片（`--overwrite` 才重跑） |

> ⚠️ **尺寸已按用户实测调大（2026-11-10 二次定档）**：中工 LOGO 是宽幅（2.62:1）。
> 原 1/20 在 720×1280 竖屏上只有 **64×24 px**，成片里几乎看不见 → 用户要求放大 5~8 倍。
> 现默认 **÷4（= 5 倍）**：720×1280 → **320×122 px**、1080×1920 → 270×103 px；
> 实测清晰可读（圆形 +「中工」+ 英文小字都不糊），转场处也不丢。
> 想更大/更小：`--ratio 2.5`（8 倍，512px，会压到人脸）、`--ratio 12`（约 1.7 倍）。
> 8 倍虽更醒目，但全画面浮动时会明显压主体；**5 倍是「醒目且不压主体」的平衡点**。
> 透明底已实证：四角 alpha=0，叠加后无白色矩形底块。

## 二、多素材拼接冻结规格

| 项 | 默认值 | 说明 |
|---|---|---|
| 输出基准 | **第一条视频**的显示宽高 + 帧率 | 横竖混排也以它为准；全是图片才用 1080×1920/30 兜底 |
| 画面统一 | **等比缩放 + 模糊压暗底填充，不裁切** | `boxblur=24:2` + `brightness=-0.12` 铺底，主体完整居中 |
| 图片素材 | 静帧，时长 **2~5s 按前后口播节奏自适应** | 默认 3s；由 Agent 读素材后写进 `edit_plan.json`，不做强制动效 |
| 画面转场 | 0.5s | `fade / dissolve / slideleft / wipeleft / smoothleft`，按内容选 |
| 声音 | **保留各段原声 + acrossfade 0.3s 交叉淡化** | 缺音轨的素材（图片/静音视频）用 `anullsrc` 补静音，保证音频链可串 |
| 编排决策 | **AI 理解内容后自动编排，方案随成片给** | 顺序、每段截取、图片时长、转场类型都写进 `edit_plan.json`，附判断依据 |
| 产物 | 两个文件 | `拼接成片_拼接版.mp4`（无水印）+ `水印版/拼接成片_拼接版_水印版.mp4` |
| 附交付 | `剪辑方案.md` / `edit_plan.json` / `拼接信息.json` / `质检报告.md` / `contact_sheet/` | 方案可编辑后重跑，重跑结果一致、可追溯 |

## 三、Agent 工作流（多素材时**必须**照做）

> 拼接的「理解内容与逻辑」由 **Agent 亲自完成**，脚本只负责可复现的执行。
> 这是本技能的核心，别的机器装了技能也是同一套流程。

```
① wm_pipeline.py <素材...> --work <work> --analyze
   → 产出 素材卡片.json（元数据 + 口播转写）、contact_sheet/sheet_XX.jpg（每条素材 8 帧网格）、
     edit_plan.json（可直接执行的默认方案：按输入顺序、图片 3s、fade）
```

**② Agent 亲自理解**（不要跳过、不要让脚本猜）
- 逐张用 ViewImage 读 `contact_sheet/sheet_XX.jpg`，看每条素材拍了什么、是横是竖、有没有黑帧/废段。
- 读 `素材卡片.json` 的 `asr` 字段了解口播主题。
- ⚠️ **ASR 只是辅助线索，不是事实**。whisper 在无人声/纯音轨上会脑补文字
  （2026-11-10 实测：sine 音轨被转成「字幕by索兰娅」）。以画面为准，明显幻觉直接忽略；
  近静音素材已由能量门自动跳过 ASR。
- ⚠️ **转写文本绝不用于「定用字」**：真片 C0131 实测把「2026」转成「2016」、
  「出路来了」转成「出入来了」—— 同音错字 / 年份错字在 ASR 上非常稳定，
  多档 beam 一致也不代表对。转写**只用来判断素材大意与叙事顺序**，
  绝不拿来写字幕、写文案、生成任何对外文字（与本项目既有铁律一致：用字以原口播稿为唯一权威）。
- 综合判断叙事逻辑（钩子 → 铺垫 → 主体 → 收尾），不要机械按文件名排。

**③ Agent 改写 `edit_plan.json`**
- `clips` 顺序：按内容逻辑重排
- 每段 `in` / `out` / `duration`：去掉明显废段，保留有效内容
- 图片 `duration`：在 **2~5s** 内按前后口播节奏定
- `transition`：按内容从 `fade/dissolve/slideleft/wipeleft/smoothleft` 里选
- **每个 clip 的 `reason` 必须写清判断依据**（方案是要交给用户看的）
- 不要改 `target` 的基准规则；不要给单素材走这条链路

```
④ 去掉 --analyze 重跑同一条命令（或 --plan <edit_plan.json>）
   → compose（无水印拼接版）→ render（加水印）→ check（量化质检）
⑤ 把 拼接版 / 水印版 / 剪辑方案.md / edit_plan.json / 质检报告.md 一起交付
```
不打断、不先问方案；用户看了不满意再点名改 `edit_plan.json` 重跑。

## 六、技术要点（别踩坑）

1. **叠加水印必须重编码视频流，「不重编码无损」做不到**。保持高清 = 原始参数不变 + 高质量编码 + 不缩放 + 音频直通 + 量化验收，不是 `-c:v copy`。
2. **ffmpeg 用 imageio 自带的**（`wm_core.find_ffmpeg()` 自动发现），不要用 PATH 那版 —— filter 语法有差异。ffprobe 只读元数据，PATH 版可以。
3. **手机竖拍容器宽高不可信**：`-noautorotate` 保持原始帧坐标系与 rotation 侧数据，读 `side_data_list.rotation`（兜底老式 `tags.rotate`）。实测 `rotation=90` 素材成片仍保留方向与原始帧尺寸，质检 PASS。
4. **色彩标记必须带走**：`-colorspace / -color_primaries / -color_trc / -color_range` 按源设置，否则 HDR/10bit 发灰。
5. **VFR 素材**加 `-fps_mode passthrough`，不复制/丢帧。
6. **轨迹写在 overlay 的 x/y 表达式里**（`eval=frame`），不预渲染 PNG 序列、不改帧率、不增加一代缩放。
7. **质检清晰度比必须排除水印区**：按确定性轨迹算出理论矩形掩掉，再比较拉普拉斯方差。
8. **轨迹可复现是硬要求**：种子只由素材相对路径决定，绝不能用 `time()` 或全局 random。
9. **★ overlay 必须 `format=yuv420`，绝不能用 `format=auto`**：`auto` 会 YUV→RGB→YUV 往返白损一代清晰度。
   实测 `auto/CRF17=0.9495`、`auto/CRF15=0.9525`（降 CRF 也救不回来）；
   `yuv420/CRF17=0.9882`、`yuv420/CRF16=0.9930`（全过）。**拼接里的模糊底 overlay 同样适用**。
10. **★ xfade 要求恒定帧率**：视频/图片混合时图片链帧率元数据会丢成 `1/0`，报
    `The inputs needs to be a constant frame rate`。正解：每段链末用
    `settb=AVTB, trim=duration=D, setpts=N/(FPS*TB), fps=FPS`，**`fps` 放最后**，
    且 `trim`/`setpts` 不要放在 `fps` 之后。
11. **★ 音频链必须补齐**：图片/无音轨素材用 `anullsrc` 生成静音，否则 `acrossfade` 串不起来。
    画面转场 0.5s 与声音淡化 0.3s 时长不同 → 末尾统一 `apad, atrim=duration=视频总时长` 对齐。
12. **拼接只做一次编码**：`wm_compose.py` 单次 filtergraph 出无水印拼接版；水印版由 `wm_render.py`
    再编码一次。两者参数完全一致（实测 1280×720 / 30fps / 16.500s / 495 帧）。
    旋转素材多出的那一步是**流拷贝**修元数据（见第 16 条），不算新增一代编码。
13. **★ 真实素材必须 CRF14，CRF16 不够**（2026-11-10 真片实测）：
    真实手机竖拍口播（1920×1080 / rot=-90 / 50fps / pcm_s16be / 29.76s）整片
    帧号对齐后清晰度比 **CRF16=0.9444（不过 0.95）**；8 秒片段对照实验
    `CRF16=0.9540`、`CRF16 去色彩标记=0.9540`（完全相同，证明色彩标记只是元数据、非元凶）、
    `CRF14=0.9741`、`CRF12=0.9869`。
    → 为了守住项目既有的「清晰度比 ≥0.95」判据，**默认从 CRF16 上调到 CRF14**，
    不靠放宽阈值放行。代价：该条成片 61MB → 93MB（约 +50%），高清优先可接受。
    实测整片 CRF14 = **0.9605 PASS**。真实动态素材各帧比值波动 0.91~0.99 属正常，看中位数。
14. **★ 带 rotation 素材必须预旋转水印，否则水印播放时是竖的**（2026-11-10 真片实证）：
    `-noautorotate` 保住了原片帧尺寸与 rotation 元数据（这是对的），但横向水印叠在
    1920×1080 横帧上，播放器旋转 90° 后会跟着变成竖向。
    正解 `render_one.prepare_watermark()`：水印按 `-rotation` 预旋转，
    目标宽高互换（96×38 → 38×96，当时为 1/20 的尺寸；现默认 ÷4 时为 320×122 → 122×320），轨迹按互换后的框计算。
    实测成片仍为 `rotation=-90`、水印尺寸 `[38,96]`，播放器视角放大后
    **圆形在左、「中」字在右、横向正立**。`wm_check.py` 单独复检时也做了同样的宽高互换。
15. **pcm_s16be 等 mp4 不兼容音轨自动回退 aac 192k**，报告里标 `aac-reencode`；
    真片（口播原片全部是 pcm_s16be）已验证，音频链不会断。
16. **★ 拼接版必须清掉残留 rotation，否则整片横躺**（2026-11-10 微信 5 素材能力测试实证）：
    ffmpeg 默认 autorotate 会把 `rotation=±90` 输入的**画面**转成正立，却仍把第一条输入的
    Display Matrix 继承到输出流 → 成片是「720×1280 正立像素 + rotation=-90」，播放器再转 90°
    就整片横躺，且下游加水印会误触发第 14 条的「预旋转水印」，错的叠错的。
    `-metadata:s:v:0 rotate=0` 对 side data **无效**；`-display_rotation` 只能放在输入侧。
    正解 `wm_compose.py` 渲染后 probe 到 rotation≠0 时，做一次**流拷贝**修正：
    `ffmpeg -display_rotation:v:0 0 -i 拼接版 -c copy -map 0 临时` 再替换原文件，
    零重编码零画质损失。修复后拼接版/水印版均 `rot=0`、720×1280 正立，抽检 9 帧全部正立。
    ⚠️ 单素材链路不能套这个修法 —— 它本来就靠 `-noautorotate` 保留原始帧与元数据（见第 3 条）。
17. **★ 抽关键帧缩略图绝不能加 `-noautorotate`**（2026-11-10 实证）：加了之后
    4 条 `rotation=-90` 素材的 contact sheet 全是横躺画面，AI「理解内容」就会看歪、编排失据。
    让 ffmpeg 自动应用 display matrix，抽出的帧与播放器视角一致（实测 720×1280 正立）。
    `wm_understand.make_sheet()` 已修。
18. **源是 `yuvj420p / color_range=pc (full)` 时，拼接版保持同标记是保真、不是缺陷**
    （微信素材实测源与成片四色标记逐项一致），不要擅自转 limited range，否则反而偏色。
19. **ASR 转写在真实口播上也会出同音错字**（2026-11-10 实测：「2026」→「2016」、
    「出路来了」→「出入来了」、把整句转成「这里有个二十七十官张同…」）。
    **转写只用于判断素材大意与场景，绝不作任何用字/字幕依据**；纯音轨/近静音还会脑补文字，
    已由能量门跳过。判断内容以正立关键帧为准。

## 七、质检判据

| 场景 | 基准 | 判据 |
|---|---|---|
| 单素材 | 成片 ÷ **原片** | 清晰度比 ≥0.95 |
| 多素材 | 水印版 ÷ **无水印拼接版** | 清晰度比 ≥0.95（保证加水印这一步不降级） |

> 拼接必须统一不同素材的分辨率/帧率，无法与单条原片逐帧比，故以「完整视频（拼接版）」为基准。
> 两个文件都落盘，正好对应「拼成完整视频之后再加水印」。

### 清晰度比的双口径（判据 ≥0.95 不变）

`wm_check.py` 同时算两个数，**都写进报告，原生损失绝不隐藏**：

| 字段 | 含义 |
|---|---|
| `sharpness_ratio` | **主判据**：原片与成片统一降到观看分辨率（短边 ≤ `VIEW_SHORT_EDGE=1080`）再比，跨分辨率可比 |
| `sharpness_native` | 原始分辨率下直接比，如实记录 |

短边 ≤1080 时不做缩放，两个数值完全一致（1080p 真片实测两组数组逐项相同）。

4K 真片 C0134（3840×2160 / rot=-90 / 25fps / 31.68s）实测：
`CRF14 slow` 原生 **0.9434**（不过）、观看分辨率 **0.9929**（过）。
8 秒对照：`CRF14 slow 原生 0.9329 → 观看 0.9867`；
`CRF14 slower 原生 0.9429`（升预设仍不够）；
`CRF12 slow 原生 0.9690`（达标，但 4K 全片约 600MB，团队批量不现实）。

→ 4K 原生口径的差值全部来自**最终 1080p 观看/交付上不可见的超高频**。
正解是统一观看尺寸比较，**不是放宽阈值、也不是堆码率让文件暴涨**。

通用检查：参数一致（宽高 / rotation / pix_fmt / 色彩标记 / 帧率，时长差 ≤0.15s、帧数差 ≤1）、
水印位置实证（改动像素落在理论框内比例 ≥0.60）、轨迹不越界、批量 0 FAIL 才归档。

- 分发包 = `zg_shuiyin_skill.zip`，解压后双击 **`安装.bat`**（GBK）即把 `skills/zg_shuiyin_skill/` 复制到
